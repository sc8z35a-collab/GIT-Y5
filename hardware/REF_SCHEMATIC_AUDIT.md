## 2. 照合により洗い出した9件の設計ミス・不足部品と修正内容

### BUG #1 [致命的・起動不能] `RK806-1` の NLDO プリレギュレータ入力 (`VCC_1V1_NLDO_S3`) が完全欠落
- **参照根拠**: Radxa ROCK 5B+ V1.2 Page 30–31 / Radxa CM5 V2.2 Page 12（`RK806-1` の `VCC13`/`VCC14` は 1.1V プリレギュレータ必須）
- **BEFORE（問題）**: `U206 (RK806-1)` に `VCC_PLDO (2.0V)` しか接続されておらず、NLDO1〜5（`VDD_0V75_S3`, `VDDA_DDR_PLL_S0`, `VDD_0V75_S0`, `AVDD_0V85_S0`, `VDD_0V75_S0_PLL`）を駆動する 1.1V 入力電源 (`VCC13`/`VCC14`) が存在しなかった。実機では PMU ロジック・DDR PLL・MIPI/USB PHY が無給電となり **MaskROM すら起動しない**。
- **AFTER（修正）**: メイン基板裏面に専用 2A 降圧レギュレータ **`U212 (SY8089AAAC)`** + `L226 (2.2µH)` + 帰還分圧 `R213 (100kΩ)` / `R214 (120kΩ)` + 位相補償 `C212 (100pF)` + 入出力デカップリング（`10µF` / `22µF` / `100nF`）を追加し、`PMIC_EXT_EN` イネーブルで **`VCC_1V1_NLDO_S3 (1.10V S3)`** を生成して `U206.VCC_NLDO` へ供給。

### BUG #2 [致命的・LPDDR5X起動不能] LPDDR5X 必須電源 `VDD2L_0V9_DDR_S3 (0.90V S3)` が欠落
- **参照根拠**: Radxa ROCK 5B+ V1.2 Page 14（LPDDR5 は `VDD1=1.8V`, `VDD2H=1.05V`, `VDD2L=0.90V`, `VDDQ=0.50V` の4系統が JEDEC 必須）
- **BEFORE（問題）**: `U301 (K3LK7K70BM-BGCP 16GB LPDDR5X)` に対し `VDD2_DDR_S3` / `VDDQ_DDR_S0` / `VCC_1V8_S3` の3系統しかなく、`VDD2L (0.90V)` が存在しなかった。また LPDDR5X 特有の **`WCK_P/N`**（Write Clock 差動ペア）、**`DDR_RESET_N`**、および **`VDDQ_DDR_CKE_S3`** フェライト分離も未配線だった。
- **AFTER（修正）**:
  - 専用 2A 降圧 **`U211 (SY8089AAAC)`** + `L225 (2.2µH)` + `R211 (56kΩ)` / `R212 (100kΩ)` + `C211 (10nF)`（`EN = VCC_1V8_S3` で LPDDR5X 電源投入シーケンス準拠）を追加し **`VDD2L_0V9_DDR_S3 (0.90V S3)`** を生成。
  - `U101 ↔ U301` 間に `LPDDR5X_CH0_WCK_P/N`, `LPDDR5X_CH1_WCK_P/N`, `DDR_RESET_N` を追加。
  - `FB301 (BLM03AG121SN1D, 120Ω@100MHz)` で `VDD2_DDR_S3 → VDDQ_DDR_CKE_S3` を分離し、LPDDR5X 周辺 MLCC を **24個 → 36個**（`22µF × 4`, `10µF × 4`, `1µF × 4`, `100nF × 24`）へ増強。

### BUG #3 [致命的・32kHz発振停止] `HYM8563TS` RTC の `CLKOUT` オープンドレイン用 47kΩ プルアップ欠落
- **参照根拠**: Radxa ROCK 5B+ V1.2 Page 29（`HYM8563TS` の `CLKOUT` および `INT` はオープンドレイン出力）
- **BEFORE（問題）**: `U102.CLKOUT → CLK_32K_RTC → U101.CLK32K_IN / U206.CLK32K` にプルアップ抵抗がなく、32.768kHz クロック信号が常に Low/Hi-Z となり PMIC スリープ遷移・RTC 計時・ディープスリープ復帰が動作不能だった。`RTC_INT_L` も未接続だった。
- **AFTER（修正）**: **`R106 (47kΩ)`**（`CLK_32K_RTC → VCC_1V8_PMU_S3`）と **`R107 (10kΩ)`**（`RTC_INT_L → VCC_1V8_PMU_S3`）を追加し、`U102.INT` を `U101.RTC_INT_L` へ結線。

### BUG #4 [致命的・PMIC OTP不一致] `RK806-1` の NLDO/PLDO 出力割当・`FB6`/`FB9` 電圧設定・`PWRCTRL1..3` 誤配線
- **参照根拠**: Radxa ROCK 5B+ V1.2 Page 30–31 / Radxa CM5 V2.2 Page 12（`RK806-1` OTP 固定テーブル）
- **BEFORE（問題）**:
  - `NLDO2/NLDO5/PLDO1/PLDO2` の出力ネットが `RK806-1` 工場出荷 OTP 電圧テーブルと食い違っていた（特に `VDD_CPU_BIG_MEM_S0` を `NLDO5` から取っていたが、正しくは `VDD_CPU_BIG1_S0` からフェライトビーズ分離）。
  - `BUCK6 (VDD2_DDR_S3 = 1.05V)` と `BUCK9 (VDDQ_DDR_S0 = 0.50V)` の外付け帰還分圧 `FB6`/`FB9` が無く、LPDDR5X 電圧に設定されていなかった。
  - `BUCK1..5` の `100Ω` ケルビンリモートセンス抵抗、`SPI2` ラインの `22Ω` ダンピング抵抗・`100kΩ` プルアップ、`PWRCTRL1/2/3`（スリープ制御ピン）、`PMIC_INT_L` プルアップ、`PWRON` ESD 保護が欠落していた。
- **AFTER（修正）**:
  - `RK806-1` OTP 通り `NLDO1..5`（`VDD_0V75_S3`, `VDDA_DDR_PLL_S0`, `VDD_0V75_S0`, `AVDD_0V85_S0`, `VDD_0V75_S0_PLL`）と `PLDO1..6`（`AVCC_1V8_S0`, `VCC_1V8_S0`, `AVDD_1V2_S0`, `AVDD_3V3_S0`, `VCCIO_SD_S0`, `VCC_1V8_PMU_S3`）を正確に再マッピング。
  - `FB6` に `R215 (110kΩ)` / `R216 (100kΩ)` + `C215 (100pF)`（$0.50\text{V}\times(1+110/100)=1.05\text{V}$）、`FB9` に `R217 (0Ω)` + `C216 (100pF)`（$0.50\text{V}$）を実装。
  - `R218..R222 (100Ω)` ケルビンセンス、`R226/R227 (22Ω)` SPI2 ダンピング、`R228/R229 (100kΩ)` SPI プルアップ、`R230 (10kΩ)` `PMIC_INT_L` プルアップ、`D201 (AZ5825-01F)` PWRON ESD、`PWRCTRL1=PMIC_SLEEP1` / `PWRCTRL2=PMIC_SLEEP2` / `PWRCTRL3=GND` を実装。
  - `FB201 (120Ω@100MHz)` + `22µF` で `VDD_CPU_BIG1_S0 → VDD_CPU_BIG_MEM_S0` を ROCK 5B+ Page 30 (`FB2300`) 通りに分離。

### BUG #5 [安全・熱保護欠落] `TSADC_SHUT_ORG` ハードウェア熱シャットダウン未接続 & `SARADC_IN0` 電源系統誤り
- **参照根拠**: Radxa CM5 V2.2 Page 9 & Page 13
- **BEFORE（問題）**: `RK3588S2` のハードウェア過熱シャットダウン出力 `TSADC_SHUT_ORG` が `PMIC_RESETB` に接続されておらず、SoC 暴走加熱時にハードウェア強制リセットがかからない状態だった。また Recovery 検出用 `SARADC_IN0_RECOVERY` の 10kΩ プルアップ `R104` が S3 ドメイン (`VCC_1V8_S3`) に繋がっており、S0 アナログ ADC 電源 (`AVCC_1V8_S0`) オフ時にリーク電流経路を形成していた。さらに 1nF フィルタと ESD が欠落。
- **AFTER（修正）**: `R108 (0Ω)` で `TSADC_SHUT_ORG ↔ PMIC_RESETB` を接続し、`R104 (10kΩ)` のプルアップ先を **`AVCC_1V8_S0`** へ修正、`C107 (1nF)` フィルタと **`D102 (ESD5451N)`** を追加。

### BUG #6 [不安定要因] `eMMC 5.1` の `VDDI` 容量不足 (`1µF` → `2.2µF`) と `D0` プルアップ欠落
- **参照根拠**: Radxa CM5 V2.2 Page 19 / JEDEC JESD84-B51
- **BEFORE（問題）**: `U302 (KLMAG1JETD-B041)` の内部コアレギュレータ出力 `VDDI` が `1µF` しかなく、さらにブート時ビジー検出に使う `EMMC_D0` の 10kΩ プルアップ抵抗および `VCC`/`VCCQ` 高周波バイパス `100nF` が不足していた。
- **AFTER（修正）**: `C301` を **`2.2µF (0201)`** へ増量、`R307 (10kΩ)` を `EMMC_D0_D7 → VCC_1V8_S3` へ追加、さらに `VCC_3V3_S3` / `VCC_1V8_S3` に各 `100nF` を追加。

### BUG #7 [電源応答不足] 外部 6A Sub-Buck (`3× RK860`) の `VSEL` / `100Ω` センス / 出力容量不足 & GPU 47µF 不足
- **参照根拠**: Radxa ROCK 5B+ V1.2 Page 30 / Radxa CM5 V2.2 Page 12
- **BEFORE（問題）**: `U207 (RK860-2 CPU_BIG0)`, `U208 (RK860-3 CPU_BIG1)`, `U209 (RK860-2 NPU)` に `VSEL` ピン接続、`100Ω` リモートセンス抵抗が無く、出力バルク容量も不足していた。`VDD_GPU_S0` の大電流過渡応答用 `47µF` バルク容量も不足。
- **AFTER（修正）**: 各 `RK860` に `VSEL = VCC_1V8_S3`、ケルビンセンス `R223/R224/R225 (100Ω)`、出力バルク `22µF × 5`（計 `110µF`/相）を配置し、`VDD_GPU_S0` へ `47µF × 2 (0603)` を追加。

### BUG #8 [基板外形クリアランス違反] 基板端から 0.30mm 未満の部品配置
- **参照根拠**: KiCad 9.0.8 ネイティブ DRC (`copper_edge_clearance >= 0.30 mm`)
- **BEFORE（問題）**: `L217..L220` 下段の `22µF` 出力コンデンサ、サイドキー BTB `J801` / `D801`、`D603 (SMF24A)`、`C601/C602`、Audio 10µF が基板外形 `Edge.Cuts` に接近し過ぎており、実製造時の Vカット／ルータ外形加工でパッド剥離・銅露出が発生する位置だった。
- **AFTER（修正）**: 該当部品を内側へ再配置または裏面実装へ移行し、**全1,727パッドで `Edge.Cuts` から `>= 0.30 mm` のネイティブ DRC 違反 0 件**を達成。

### BUG #9 [検証網羅性] 電源シーケンス・必須ストラップの自動回帰チェック不足
- **AFTER（修正）**: `hardware/verify_erc.mjs` を 104項目へ拡張し、`VDD2L_0V9_DDR_S3` / `VCC_1V1_NLDO_S3` / `CLK_32K_RTC` 47kΩ PU / `TSADC_SHUT_ORG` / `eMMC VDDI 2.2µF + D0 PU` / 全8系統 I2C プルアップ / 差動ペア整合 / 浮遊ネット 0件 / 2D Courtyard 衝突 0件を毎ビルド検証可能にした。

## 3. 【プロ設計者としての率直な開示】実機テープアウト・Android起動までに残る現実的ギャップ

本設計は概念モックではなく、実在部品・実効電源シーケンス・KiCad 9.0.8 ネイティブDRC完全合格（0/0/0）・JLCPCB実ガーバー解析合格まで到達しているが、**このまま工場へ発注して Android OS を初回スピンで安定起動させるには、以下の4つの工学的ギャップを解消する必要がある**。これらを隠さず明記する。

### ギャップ ①：BGA フルボール数（1,253ピン等）ではなく「機能グループ代表ピン」でのネットリスト／フットプリント実装
| IC | 実チップ物理ボール数 | 本ネットリスト／PCBでの実装パッド数 | 意味すること |
| :--- | :---: | :---: | :--- |
| `U101` (`RK3588S2`) | **1,253 balls** (FCCSP1253, 0.4mm/0.5mm pitch) | **213 pads**（電源・主要高速バス・全ペリフェラル代表ピン） | 電源/GND多重ボール（数百本）および64-bit DDR DQ0..63・DMI・CS 個別ボールの完全1:1展開が別途必要 |
| `U301` (`K3LK7K70BM-BGCP` LPDDR5X) | **315 balls** (FBGA315) | **21 pads**（チャネル別グループ化） | 315ボール全展開＋各バイトレーン単位の等長配線が必須 |
| `U302` (`KLMAG1JETD-B041` eMMC 5.1) | **153 balls** (FBGA153) | **9 pads**（`D0..D7` バス統合表現） | 8本個別データラインの展開が必須 |
| `U206` (`RK806-1`) | **68+1 pins** (QFN-68) | **49 pads**（全電源/制御機能展開済、多重PGND/VIN統合） | 多重VIN/PGNDピンの1:1展開とサーマルビア配列が必要 |

### ギャップ ②：高速シグナルインテグリティ（SI）・パワーインテグリティ（PI）・等長配線
- **LPDDR5X-6400**（実効 3.2GHz WCK / 6400 MT/s）は、シングルエンド `40Ω` / 差動 `80Ω` インピーダンス制御、バイトレーン内 `±2.5 mil` (`±0.06 mm`) の厳密な等長配線（蛇行チューニング）、および専用リファレンス GND プレーン直下でのマイクロストリップ／ストリップライン設計が必須。現行自動ルータ（`hardware/route_kicad_pcb.mjs`）は接続性と最小クリアランスを完全保証するが、**長さ合わせ（スキュー調整）・差動結合インピーダンス・SI/PI 電磁界シミュレーションは未実施**である。
- MIPI C-PHY/D-PHY (45MP カメラ・LTPO OLED)、USB 3.1 Gen2 (10Gbps)、PCIe Gen3 (5G モデム) についても同様に `85Ω/90Ω/100Ω` 差動ペア結合配線とスキュー調整が量産前に必要。

### ギャップ ③：基板層構成と厚み（標準16層スルーホール `1.6mm` vs 量産Any-Layer HDI `0.8mm`）
- 本プロジェクトでは、KiCad 9.0.8 ネイティブ DRC 0件かつ JLCPCB 標準製造ラインで確認できるよう、**スルーホール POFV (`0.15/0.25mm`) のみの16層基板**として 100% 配線を完了した。
- しかし JLCPCB の実見積もり／自動DFM により、**標準 FR-4 16層は最小板厚が `1.6mm` であり、さらに `1.6mm` 板厚ではアスペクト比超過 (`10.67:1`) のため `0.15mm` ドリルが選択不可（最小 `0.20mm` ドリル）**であることが実証された。
- 一方、RK T4 の 3D 筐体（総厚 `9.40mm`・干渉0）に収まる基板厚は **`0.80mm`** である。したがって実機量産には、市販フラッグシップスマートフォン同様に **10〜12層 Any-Layer HDI（ELIC / 1+N+1 または 2+N+2、レーザーマイクロビア `0.075/0.15mm`、板厚 `0.80mm`）** への移行が物理的に必須となる。

### ギャップ ④：メザニン RF 基板（140部品）およびデカップリング総数
- 5G/Wi-Fi 6E/GNSS/NFC を搭載するメザニン基板（`140部品`）はネットリスト定義・2D配置・ERC検証（`verify_erc.mjs`）および 3D 干渉検証まで完了しているが、KiCad PCB 実配線およびガーバー出力はプライマリメイン基板（`507部品 + J901`）のみ実施している。5G サブ6 (`n77/n78/n79` 最大 5GHz) のアンテナ整合回路・50Ω コプレーナ導波路・RF シールド缶直下ビアフェンスは RF 専任の電磁界解析（HFSS/ADS 等）が必要。
- 全基板合計の MLCC 実装数は **402個**（メイン基板＋メザニン＋カメラモジュール）まで引き上げたが、フル 1,253ボール展開時の SoC 直下キャビティ容量は Radxa CM5 単体（436個）〜市販ハイエンドスマホ（800〜1,200個）並みへの追加が必要となる。

### ギャップ ⑤：JLCPCB 実部品ライブラリ照合で検出した BOM パッケージ表記ズレ（7件）
JLCPCB 公開 SMT ライブラリ API との全数照合（`hardware/mfg/jlcpcb_bom_stock_audit.json`）により、以下 7 品目の実パッケージと現行ネットリストの `pkg` ラベルにズレがあることが判明した（実機実装前にランドパターン修正が必要）：
1. `HYM8563TS` (`U102`): 現行表記 `DFN-8 (2x2mm)` → 実パッケージ **`MSOP-8`**（`C5156238`）
2. `BAT54C` (`D101`): 現行表記 `SOT-323` → 実パッケージ **`SOT-23`**（`C2135`；`SOT-323` 品番は `BAT54CW`）
3. `K3LK7K70BM-BGCP` (`U301`): 現行表記 `315-FBGA` → 実パッケージ **`FBGA-496`**（`C50327268`）
4. `TAS2562YFPR` (`U802/U803`): 現行表記 `DSBGA-30` → 実パッケージ **`DSBGA-36`**（`C2879588`）
5. `PESD5V0S4UD` (`D801`): 現行表記 `DFN2510` → 実パッケージ **`SOT-23-6`**（`C2987082`）
6. `BLM03AG121SN1D` (`FB1009..FB1012`): 現行表記 `0402` → 実パッケージ **`0201`**（`C97850`；`0402` 品番は `BLM15AG121SN1D`）
7. `TPD6E05U06RVZR` (`D701`): 現行表記 `DFN2510` → 実パッケージ **`USON-14 (1.4×3.5mm)`**（`C962978`）
